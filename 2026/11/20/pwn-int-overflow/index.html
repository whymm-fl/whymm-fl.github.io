由于scanf与read是2个不同的缓冲区两个不同的缓冲区

  1. 用户空间缓冲区（stdio缓冲区）：
    • 由C标准库（libc）维护。
    • scanf、gets、fgets、printf等标准I/O函数使用的是这个缓冲区。
    • 它的目的是为了减少系统调用，提高效率（一次性从内核读一大块，比如4096字节）。
  2. 内核空间缓冲区（系统调用缓冲区/socket缓冲区）：
    • 由操作系统维护。
    • read、write、recv、send等系统调用直接与这个缓冲区交互。

故可以不用考虑sendline残留的\n，直接用send

同时getc（stdin）又把\n给取走了，故后续状态这个缓冲区又变空了

level3

调用fgets函数（读到\n会停止，同时末尾自动补\0）

由图知最多读8个字节（fgets末尾会自动补\0）

故不能用sendline（结尾会补\n使得缓冲区多出来一个\n影响后面运行）

每个元素的大小为1个字节，一共读10个元素故fread读10个字节

再用\x00补齐字节数 好处：

  • 不像 \n（0x0a）：\n 会触发 fgets 截断，会在缓冲区里残留并污染后续的 scanf 或 read。\x00 不会触发任何格式化解析。
  • 不像可见字符（如 a、1）：可见字符会被后续的 strncmp、strlen 视作有效数据，可能导致越界比较或长度计算错误。\x00 是极其安静的“隐形人”。
  • 不触发空白符跳过：它也不会像空格那样被 scanf 跳过（scanf 跳过的是空白符，\x00 不是空白符）。

分析代码

第三个参数7。

7 = 1 | 2 | 4，代表：

  • 1：可读
  • 2：可写
  • 4：可执行

所以这块内存既能写，又能执行。

buf 就是这块内存的地址

(void (*)(void))buf 是一个强制类型转换：

  • 把 buf 这个“无类型指针”转换成“函数指针”。
  • 转换后，buf 的值（也就是那个内存地址）被当作一个函数的入口地址。

而这个函数就是写入的那段 shellcode

攻击脚本

  1. shellcraft.sh() 生成汇编代码字符串；
  2. asm() 把这段汇编代码翻译成机器码字节；
  3. 最终 shellcode 就是一个 64 位 Linux 下执行 /bin/sh 的机器码：execve("/bin/sh", NULL, NULL)
  4. arch='amd64'含义：指定目标 CPU 架构为 x86-64，也就是 64 位 架构。

2.mmap 取出来的这块内存可读、可写、可执行，不受 NX 对栈的限制。

攻击脚本

反思：为什么要栈对齐

在 64 位 CPU 的指令集里，有一类特殊的指令叫 SSE 指令（比如 movaps）。

这类指令在执行时，强制要求内存地址必须是 16 的倍数。

如果 CPU 发现你要操作的地址不是 16 的倍数，它就会直接抛出异常（报 SIGSEGV），程序瞬间崩溃。

而 system 函数是 libc 里的“大杂烩”，它内部为了实现高性能，大量使用了这类 SSE 指令。所以，在调用 system 时，栈指针 rsp 必须刚好是 16 字节对齐的。

用溢出攻击时，发生了什么？

通过栈溢出覆盖返回地址，然后用一条 ret 指令强行跳过去。跳过了正常的 call 指令此时栈上少了一个返回地址

  1. 跳过去时：ret 指令弹出了填写的目标地址，rsp 增加了 8 字节。
  2. 进入目标函数（比如 heavens_door）时：此时 rsp 的地址是 16n - 8（不对齐）。
